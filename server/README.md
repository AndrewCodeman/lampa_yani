# Yani resolver

Self-hosted service that turns an Alloha player page into a plain HLS URL that
Lampa's internal player, or any external media player, can open.

## Зачем это нужно

Alloha не отдаёт прямой поток:

* страница плеера отказывается работать вне iframe;
* манифест требует заголовки `authorizations` и `accepts-controls`, причём
  второй (`edge_hash`) обновляется по WebSocket примерно раз в две минуты;
* токен внутри пути `master.m3u8` одноразовый — кто первым сделал запрос, тот и
  получил поток, второму прилетает `403 token_decrypt`.

Браузер не может добавить эти заголовки к кросс-доменному манифесту: получается
CORS preflight, на который CDN не отвечает. Поэтому расширение Lampa не в
состоянии решить задачу само — нужен внешний процесс.

Сервис поднимает headless-браузер, открывает в нём обёртку **с origin самой
Alloha** (только так обёртка становится same-origin с iframe и может
инструментировать его сеть), забирает оттуда живую сессию и проксирует манифест
и сегменты, подставляя актуальные заголовки.

Подход повторяет то, как это сделано в Android-приложении YummyTV
(`AllohaExtractor.kt` + `AllohaStreamProxy.kt`).

## Установка

```bash
cd server
npm install
npm start
```

`npm install` дополнительно скачивает Chromium для Playwright (~150 МБ).

Сервис слушает `0.0.0.0:8790`. В настройках расширения (YummyAnime → «Сервер
резолвера») укажите `http://<ip-машины>:8790`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `YANI_RESOLVER_PORT` | `8790` | Порт |
| `YANI_RESOLVER_HOST` | `0.0.0.0` | Интерфейс |
| `YANI_RESOLVER_IDLE_MS` | `300000` | Через сколько закрывать простаивающую сессию |
| `YANI_RESOLVER_HEADLESS` | `true` | `false` — показать окно браузера (отладка) |
| `YANI_RESOLVER_VERBOSE` | `false` | Подробный лог |

## API

* `GET /health` → `{"ok":true,"version":"1.0.0","sessions":0}`
* `GET /resolve?url=<iframe-url>` → `{"url":"http://…/hls/<id>/master.m3u8","source":"yani-resolver","session":"<id>"}`
* `GET /hls/<id>/master.m3u8` — проксированный манифест
* `GET /hls/<id>/p?u=<base64url>` — проксированный сегмент или вложенный плейлист
* `GET /release?session=<id>` — закрыть сессию

Сессия держится живой, пока её запрашивают, и закрывается после
`YANI_RESOLVER_IDLE_MS` простоя.

## Ограничения

* Одна сессия на URL серии: несколько устройств, играющих одну и ту же серию,
  делят один браузерный контекст.
* Смена CDN-узла в середине просмотра приводит к перезапуску сессии — плеер
  увидит короткую паузу на буферизацию.
* Качество выбирает сам плеер из вариантов внутри проксированного мастера:
  ссылки из `bnsi` отдаются только для отображения, на живой сессии они уже
  отвечают `403`.
